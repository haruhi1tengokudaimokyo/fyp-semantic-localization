# Gazebo 同地图 ACE 工程验证

使用官方 ACE 编码器、场景坐标回归网络和 DSAC*，为本次 Gazebo 地图重新训练了专用定位头；没有使用 7-Scenes 定位头替代。地图为 `procthor_scene03000_structure_v1`，地图 SHA256 和编码器/定位头 SHA256 保存在 `model_binding.json`。

192 张独立参考 RGB 及其合法离线相机位姿用于训练；561 张连续查询图像用于评价，参考/查询图像 SHA256 无交集。配置为 1,000,000 个缓存特征、16 epochs、batch 5120、seed 2089；训练耗时 345.36 秒，峰值显存分配 3443.37 MiB。本轮是受 6GB GPU 约束的新地图工程试验，不能与之前 7-Scenes 的原版 8M 正式复现混称。

查询进程仅输入 RGB、标定、时间戳和地图标识，使用已绑定的定位头。GT 只在独立 CPU 评价中读取。`read_guard_verification.json` 记录了真实子进程尝试读取受保护 GT 文件并触发 `PermissionError` 的测试；该机制是 Python 文件打开审计保护，不是操作系统或任意 C/C++ 系统调用的隔离保证。

原始查询位姿在原地图坐标系直接评价，没有轨迹拟合、插值、置信度过滤或删除错误输出：

| 指标 | 结果 |
| --- | ---: |
| 输出位姿 / 查询数 | 561 / 561 |
| 5 cm / 5° 成功率 | 235 / 561，41.89% |
| 25 cm / 10° 成功率 | 446 / 561，79.50% |
| 1 m / 30° 成功率 | 497 / 561，88.59% |
| 平移中位数 / RMSE / P95 | 0.0593 / 1.9200 / 3.3125 m |
| 旋转中位数 / P95 | 0.7324° / 63.4592° |
| 算法耗时均值 / P95 | 171.85 / 213.33 ms |

数学上成功输出不等于定位正确：64 帧未达到 1 m / 30°，长尾错误显著，必须由独立的时间一致性、内点数等门控保护融合器。此处指标没有应用融合门控，也没有依据查询 GT 调阈值。`reprojection_error_px` 表示全部有效正深度场景坐标的中位数，不是 DSAC 内点中位数。

本地图来自开发用建筑的新 Gazebo 渲染域；不能据此宣称未见建筑泛化或真实机器人部署有效。训练和批量推理使用 GTX 1660 SUPER，批量耗时不能证明多模型并发在线性能。
